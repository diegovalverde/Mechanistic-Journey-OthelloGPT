# Transformer Background

This appendix explains only the Transformer architecture needed to read the Othello-GPT investigation. The model in this book is not GPT-2 itself. It is a small GPT-2-style decoder-only Transformer trained on Othello move sequences. Its verified configuration is:

| Quantity | Value |
| --- | ---: |
| Blocks | 8 |
| Layer indices | 0 through 7 |
| `d_model` | 512 |
| Attention heads per block | 8 |
| `d_head` | 64 |
| MLP width | 2048 |
| Vocabulary size | 61 |
| Context length | 59 |
| Activation | GELU |
| Normalization | `LNPre` |

Layer numbers are zero-based. Layer 7 is the eighth and final block.

## Tokens

The model reads a game transcript as a sequence of tokens. In ordinary language models, tokens might be words, word pieces, punctuation, or bytes. In this Othello model, tokens correspond to move locations in an Othello transcript. The output vocabulary has 61 tokens, reflecting the move-token setup used by the original notebook and reproduced experiments.

The model is trained to predict the next token from the previous tokens. It is not given the board as an input. It sees a history like "C4, C3, D3, ..." as a token sequence and must assign scores to possible next moves.

Why this matters for the book: the board state is hidden from the input. If board information is recoverable from the model's activations, the model must have computed it from the move transcript.

The token sequence is not the board. This sounds obvious, but it is the central reason Othello is useful. A move transcript is an observation stream. The board is the latent state generated by applying game rules to that stream. Two pieces of code can therefore disagree in a meaningful way: the Transformer consumes token IDs, while the simulator computes board labels and legal moves. The probe and intervention experiments connect these two worlds.

## Embeddings

A token is an integer ID, not a vector with semantic content by itself. The model begins by looking up an embedding vector for each token. Each embedding lives in the residual-stream dimension:

```text
[d_model] = [512]
```

For a sequence of positions, the embedded input has shape:

```text
[batch, pos, 512]
```

The embedding is the model's learned starting representation of a move token. It does not itself know the whole board. It is simply the first vector written into the stream that later layers will modify.

Why this matters for the book: every later residual activation is built from these initial token vectors plus positional information and component updates.

## Positions

The same move token can mean different things at different times in the game. A move at position 5 in a transcript is not the same situation as the same square at position 40. The model therefore also needs information about token position.

Position information lets the model distinguish the first move, the second move, and so on up to the context length `n_ctx = 59`. The model's computation is still sequence based: each row in the residual stream corresponds to one transcript position.

Why this matters for the book: most experiments measure the final prefix token position, because that row is where the model has accumulated information needed to predict the next move.

The final prefix position does not mean the final move of the whole game. It means the final token in the currently analyzed prefix. A prefix of length 28 has a different final position from a prefix of length 45. The model can process up to `n_ctx = 59` positions, and each prefix creates a prediction problem at its own last row.

## The Residual Stream

The residual stream is the central communication channel of the Transformer. At each token position, it is a 512-dimensional vector. Every block reads from it, writes updates to it, and passes the result forward.

For a batch of sequences:

```text
residual stream shape: [batch, pos, 512]
```

A useful mental model is a running workspace at each token position. The embedding and positional information initialize the workspace. Attention and MLP components then add updates. The residual stream after several blocks is a sum of many contributions.

This does not mean the residual stream is a clean table of named variables. A coordinate is not "the C4 feature" or "the legality feature." Information can be distributed across directions and subspaces.

Why this matters for the book: the board probe reads from residual-stream activations, semantic interventions add directions to residual-stream activations, and Jacobians differentiate downstream outputs with respect to residual-stream activations.

## Causal Attention

Attention is the operation that lets information move across token positions. In a decoder-only Transformer, attention is causal: the row for position \(t\) can attend to positions up to \(t\), but not to future positions.

In Othello terms, when predicting the next move after a prefix, the final token position can use earlier moves in the same transcript. It cannot use moves that have not happened yet.

Attention computes a weighted mixture of information from previous positions. The crucial point is:

**attention mixes across token positions.**

If an earlier move matters for the current board, attention gives the model a mechanism for moving information from that earlier token row into the current row.

Why this matters for the book: Othello legality is not a property of the last token alone. It depends on the board implied by the whole move history. Attention is the architecture's cross-position routing mechanism.

Causal masking is what makes this a next-token model rather than a model that sees the whole future transcript. During the prediction after a prefix, future moves are not available to the current position's attention computation. This matters for the scientific interpretation: if the model predicts legal moves, the information must come from the prefix and learned structure, not from future tokens.

## Queries, Keys, and Values

Each attention head constructs three kinds of vectors:

- queries, which ask what the current position is looking for;
- keys, which describe what each source position offers for matching;
- values, which carry the information to be mixed.

For a target position, the head compares its query with source keys. These comparisons produce attention scores. After masking future positions, the scores become attention weights. The head then takes a weighted sum of value vectors.

The details are important only because they separate two questions:

- where does the head attend?
- what information does the head write after attending?

Attention patterns answer the first question. Head result or attention output vectors answer the second. The book treats attention patterns as hypothesis-generating unless causal tests show that a head's written output matters.

Why this matters for the book: Chapter 8 inspects layer-7 attention but does not claim an attention circuit from patterns alone.

## Attention Heads

Each block has 8 attention heads. A head is a smaller attention mechanism inside the block. Each head has internal width `d_head = 64`, but after its output projection it writes into the shared 512-dimensional residual stream.

When TransformerLens exposes per-head results at `blocks.L.attn.hook_result`, the shape is:

```text
[batch, pos, head, d_model]
```

For this model:

```text
[batch, pos, 8, 512]
```

Summing across the head axis, plus the attention output bias where applicable, gives the total attention update for the block. The book compares individual layer-7 heads with MLP7 because all of them eventually write into the same residual-stream dimension.

Why this matters for the book: component attribution and ablation in Chapter 8 rank L7H0 through L7H7 and MLP7 as candidate contributors to the legality contrast.

## Attention Output

After a head mixes value information from previous positions, it writes a vector into residual space. The block-level total attention output is cached at:

```text
blocks.L.hook_attn_out
```

For this model the tensor shape is:

```text
[batch, pos, 512]
```

This is the attention update before it is added to the residual stream. In the sequential block used here:

```text
resid_mid = resid_pre + attn_out
```

Why this matters for the book: attention output is an additive component write. We can compare it to gradients, ablate it by replacement, and ask whether it contributes to legality-sensitive computation.

## MLPs

Each block also has an MLP. Unlike attention, the MLP acts position-wise:

**MLPs act position-wise on the residual information already present there.**

This means the MLP at the final prefix token does not directly scan earlier token positions. It receives the current residual row after attention has already had a chance to move information into that row. The MLP can then transform, combine, gate, and rewrite information present in that position's residual vector.

The MLP has width `d_mlp = 2048`. For one token position, the schematic computation is:

$$
p = x W_\text{in} + b_\text{in}
$$

$$
g = \mathrm{GELU}(p)
$$

$$
m = g W_\text{out} + b_\text{out}.
$$

The pre-activation \(p\) and post-activation \(g\) each have 2048 coordinates. The output \(m\) returns to 512 dimensions so it can be added to the residual stream.

Why this matters for the book: MLP7 was the strongest tested layer-7 component under both attribution and ablation. Chapter 9 then asks what its candidate neurons detect or write.

Because an MLP acts independently at each position, it is tempting to think it cannot implement relational structure. That would be too quick. The MLP cannot directly attend to earlier positions, but it can read a residual row that already contains information routed there by attention and preserved by earlier residual additions. A position-wise MLP can therefore transform relational information if that information is already present in the current row.

## GELU

GELU is the nonlinear activation function used inside the MLP. It sits between the input projection and output projection. Without a nonlinearity, a stack of linear maps would collapse into one large linear map, aside from attention's data-dependent mixing. With GELU, MLP neurons can respond differently depending on activation magnitude.

In the MLP equations:

$$
g = \mathrm{GELU}(p)
$$

the vector \(g\) is the post-activation neuron vector. TransformerLens caches this at:

```text
blocks.L.mlp.hook_post
```

Why this matters for the book: candidate MLP7 neuron attribution uses post-activation values together with output-weight write directions.

This is also why the book distinguishes a neuron's input side from its output side. The input side determines when the neuron activates. The output side determines what residual direction it writes when active. A neuron can have unclear input-side semantics while still writing in a legality-relevant direction.

## Residual Connections

A residual connection adds a component output to the stream instead of replacing the stream:

$$
r^\text{mid}_L = r^\text{pre}_L + a_L
$$

and then:

$$
r^\text{post}_L = r^\text{mid}_L + m_L.
$$

Here \(a_L\) is attention output and \(m_L\) is MLP output. The residual connection lets earlier information persist while later components add new information.

Why this matters for the book: interventions can be made by adding small vectors to the residual stream, and attribution can compare additive component writes to downstream sensitivities.

## Pre-Normalization and LNPre

This model uses `LNPre`. In the block path, normalization is applied before attention and before the MLP. The verified block structure is:

```text
hook_resid_pre
attention input normalization
attention
hook_attn_out
residual add
hook_resid_mid
MLP input normalization
MLP
hook_mlp_out
residual add
hook_resid_post
```

The normalization changes the vector read by a component, but the hook names used in the book still identify the residual states and component writes around the residual additions. In this TransformerLens implementation, `LNPre` performs the centering and scaling parts of LayerNorm without learned LayerNorm weights or biases, because the weights have been folded.

Why this matters for the book: if we say an MLP reads `resid_mid`, strictly it reads the normalized version of that residual state. The hook tells us where the residual stream is observed, but the component may internally receive a normalized input.

This is one reason hook-level descriptions should be precise. An edit at `hook_resid_mid` changes the residual state before the MLP input normalization. An edit at `hook_mlp_out` changes the vector after the MLP has already done its nonlinear computation. Those interventions can have very different meanings even if both tensors ultimately affect the same final logits.

## One Full Block

Putting the pieces together, one non-attention-only block in this model looks like this:

$$
a_L = \mathrm{Attention}_L(\mathrm{LNPre}_1(r_L))
$$

$$
r_L^\text{mid} = r_L + a_L
$$

$$
m_L = \mathrm{MLP}_L(\mathrm{LNPre}_2(r_L^\text{mid}))
$$

$$
r_{L+1} = r_L^\text{mid} + m_L.
$$

The book often uses hook names instead of equation names:

| Mathematical object | TransformerLens hook |
| --- | --- |
| \(r_L\) | `blocks.L.hook_resid_pre` |
| \(a_L\) | `blocks.L.hook_attn_out` |
| \(r_L^\text{mid}\) | `blocks.L.hook_resid_mid` |
| MLP pre-activation | `blocks.L.mlp.hook_pre` |
| MLP post-activation | `blocks.L.mlp.hook_post` |
| \(m_L\) | `blocks.L.hook_mlp_out` |
| \(r_{L+1}\) | `blocks.L.hook_resid_post` |

Why this matters for the book: mechanistic claims need locations. A claim about `blocks.4.hook_resid_post` is different from a claim about `blocks.7.hook_mlp_out`.

## The Eight-Block Stack

The model has eight blocks:

```text
0, 1, 2, 3, 4, 5, 6, 7
```

The Chapter 2 board probe reads from `blocks.4.hook_resid_post`. Chapter 4 uses the same layer-4 residual site for local Jacobian-predicted interventions. Chapter 5 transports a layer-4 semantic direction downstream. Chapter 7 finds that capture-line legality enrichment is strongest at layer 7 among tested layers. Chapter 8 opens layer 7 and compares the eight heads plus MLP7. Chapter 9 studies candidate neurons inside MLP7.

The progression matters. Layer 4 is where a board representation is highly decodable. Layer 7 is where the tested legality-sensitive capture geometry becomes strongest. Those are not the same claim.

Why this matters for the book: the investigation moves from representation to downstream use and then to component-level candidates.

## Unembedding

After the final block, the model applies final normalization and then an unembedding map to produce logits over move tokens. The unembedding is a learned linear readout from residual space to vocabulary space.

For one final residual vector:

```text
[512] -> [61]
```

The output is not a probability distribution yet. It is a vector of logits.

Why this matters for the book: gradients of logits or legality contrasts with respect to earlier residual activations include all downstream blocks plus final normalization and unembedding.

## Logits

A logit is an unnormalized score for an output token. Higher logits usually mean the model assigns higher probability after softmax, but the book often works directly with logits because differences in logits are easier to analyze.

Chapter 7 defines a legality contrast for a selected legal move:

$$
L_m^\text{legality}
= z_m - \operatorname{mean}_{j \in I} z_j,
$$

where \(I\) is the set of currently illegal empty-square moves. This is not the same as raw move preference among legal moves. It tries to isolate how much the model separates the selected legal move from illegal empty-square alternatives.

Why this matters for the book: the scalar target being differentiated determines the meaning of the gradient. A raw E3 logit gradient and an E3 legality-contrast gradient ask different questions.

Softmax turns logits into probabilities by exponentiating and normalizing them. The book rarely needs the probability formula because most experiments compare logit differences or gradients of logit-derived contrasts. This is standard in mechanistic interpretability: logit differences often isolate the model's internal scoring geometry more directly than probabilities, whose values are coupled by normalization across all vocabulary tokens.

## Decoder-Only Prediction

Othello-GPT is decoder-only. It reads previous tokens and predicts the next token. There is no encoder that receives a separate board representation, no cross-attention to an external state, and no explicit legal-move engine inside the architecture.

That makes the mechanistic question sharp. The model has to build whatever useful state it needs inside its own residual streams. The board probe asks whether the hidden board is linearly decodable from those streams. The intervention and Jacobian experiments ask whether changing those streams changes move scores. The layer and component analyses ask where the late legality-relevant transformation appears.

Decoder-only also explains why attention is causal. At position \(t\), the model can use tokens at positions `<= t`. It cannot inspect the answer token at `t+1`. The output logits at position \(t\) are the prediction for the next move.

Why this matters for the book: every experiment on the final prefix position is an experiment on the model state immediately before it predicts the next move.

It also clarifies why the model can play both sides without receiving a separate "side to move" feature in the prose. The side to move is implicit in transcript position: players alternate. The model may represent board state relative to the current player, which is why mine/theirs probe labels are more natural here than fixed black/white labels.

## Reading the Architecture Figures

The architecture figures in the book are pedagogical diagrams, not new measurements. When a figure shows a residual stream as a horizontal channel, it is representing the `[batch, pos, 512]` tensor abstractly. When it shows attention arrows from previous moves to the current token, it is representing the kind of cross-position mixing attention can perform, not claiming that a particular head has been causally proven to route that exact information.

Similarly, figures that place MLP7 after layer-7 attention reflect the verified block order. They do not prove MLP7 implements the Othello rule. The evidence for MLP7 comes later from attribution and ablation.

Why this matters for the book: diagrams are maps of possible computation. The experimental chapters decide which parts of the map have evidence.

## What the Architecture Does and Does Not Prove

The architecture tells us where information can flow:

- attention can mix information across token positions;
- MLPs can transform information position-wise after attention has routed it;
- residual connections preserve and add component writes;
- unembedding turns final residual states into move logits.

The architecture alone does not prove a world model, a legality circuit, or a rule neuron. Those require measurements. The book's evidence comes from probes, interventions, Jacobians, layer sweeps, component attribution, component ablation, neuron analyses, matched controls, and negative results.

This is why the Transformer background belongs in an appendix. It supplies the machine diagram. The main chapters ask what this particular trained machine actually learned to do.
